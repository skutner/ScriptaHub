From generated language to delegated action

The book begins with a precise boundary: agency appears when model output can alter control flow, persistent state, or the external world. A language model alone proposes continuations; an agentic runtime interprets some continuations as database queries, code execution, file edits, service calls, messages, approvals, or decisions to continue. The distinction changes everything. A mistaken sentence can mislead, but a mistaken action can expose data, spend money, damage systems, or initiate further actions before a person notices.

The contemporary agent is therefore best understood as a probabilistic policy embedded inside a software system. The runtime supplies observations, limits available actions, executes authorized operations, preserves state, and determines what evidence returns to the model. Agency is a spectrum of delegated control rather than a claim about consciousness. A router already exercises limited agency; a tool-using loop exercises more; a coding system with workspace access exercises more again. Risk depends on authority, reversibility, observability, and redress—not on the model’s personality or fluency.

The minimum runtime and its recurring patterns

A minimal agent needs an objective, model, action interface, observation channel, state, and stopping rule. Production systems add context management, typed tools, planning or routing, policy enforcement, sandboxes, tracing, verification, recovery, and meaningful human oversight. Each component answers a particular weakness: typed interfaces constrain ambiguous language, explicit state reduces transcript dependence, verification checks unsupported completion, traces make nondeterministic behavior diagnosable, and escalation reserves decisions that automated evaluators cannot legitimately settle.

The book organizes current designs as combinations of patterns rather than rival schools. Prompt chains and workflows store known dependency structure. Routers select models, tools, skills, or specialist paths. Parallel execution reduces latency or generates alternatives. ReAct loops adapt step by step to observations. Planner-executor systems separate decomposition from local work, while graphs hold durable state outside conversational history. Reflection and evaluator-optimizer loops add criticism; multi-agent arrangements distribute expertise or independent judgment. The correct composition depends on task variability, feedback, cost, and consequence.

Why open-ended loops break

ReAct remains foundational because it grounds language in environmental feedback and handles tasks whose shape cannot be predicted. Yet its transcript-centered strength becomes a weakness over long trajectories. Local choices can drift from the original specification, observations accumulate into bloated context, errors propagate, plans become implicit, and sequential tool calls inflate latency and cost. Asking a model to produce a plan does not guarantee planning competence, while asking it to explain its reasoning does not turn generated traces into faithful access to an internal mind.

Tools improve grounding but enlarge the attack surface. Instructions can arrive through untrusted content, interfaces may be underspecified, actions may not be idempotent, and the agent can mistake a plausible result for successful execution. Memory introduces poisoning, privacy, retention, and stale-state risks. Reflection can repeat the original error, and multiple agents can share correlated blind spots while adding coordination failures. Evaluation is difficult because model, prompt, tool versions, environment, scaffold, and scorer jointly determine results. A benchmark score without system configuration and cost is weak evidence.

Harnesses as the systems layer

The harness is the scaffold that converts uncertain model competence into operational behavior. It owns sessions, permissions, tool discovery, context selection, scheduling, checkpoints, model routing, budgets, transactions, logs, and recovery. It should expose the smallest amount of adaptive discretion that covers the task distribution. A disposable coding sandbox can tolerate exploration; a production database requires scoped capabilities, approvals, validation, and compensating actions. The same model can therefore belong to systems with radically different trust properties.

Protocols improve interoperability but do not supply governance by themselves. Standardized connections can let agents discover tools, resources, and other agents, yet the enclosing runtime must still decide identity, authentication, confidentiality, authority, cancellation, accountability, and evidence. Evaluation harnesses are equally important: they preserve environments and trajectories, apply several kinds of scoring, compare cost and latency, and support regression analysis. The harness era does not make prompting obsolete. It makes prompts versioned policy material inside a larger, testable control system.

The design triangle

The book treats trustworthiness, efficiency, and generality as a joint design surface. A fixed workflow can be cheap and auditable but brittle outside its intended cases. An unconstrained planner can cover novelty while consuming more tokens, time, tools, and review—and making failures harder to localize. Trust controls can slow execution, while optimization can remove context or checks that carried essential nuance. There is no globally best point. Architecture selection must follow local error costs, observability, reversibility, regulation, and value.

The proposed reconciliation is bounded generality. Use broad models where semantic interpretation is genuinely needed, but move stable operations into explicit workflows, code, database abstractions, validators, and reusable skills. Preserve fallback to broader reasoning when the structure encounters an exception. Measure accepted quality rather than raw output, include verification and review in total cost, and route simple work to cheaper interpreters where justified. Autonomy is not the goal in itself; the goal is the smallest adaptive freedom that handles real variation without destroying assurance.

ScriptaHubAgentLib, MRP-VM, and cultivable competence

The project-specific chapters present engineering hypotheses rather than universal benchmark victories. ScriptaHubAgentLib places a MainAgent at an orchestration boundary and coordinates distinct executable skill families, sessions, and controlled model access. Its stance is progressive formalization: recurring successful behavior should become reusable structure, while genuinely open problems retain a broader agentic path. The architecture should be evaluated on selected task families against equivalent-tool baselines, including context loss, review burden, latency, cost, and failure recovery.

MRP-VM extends this direction through Agentic Knowledge Units, or AKUs: inspectable units combining knowledge, interpretation, interfaces, and evaluation. Named state, explicit dependencies, forkable working knowledge, and several bounded agents aim to reduce transcript bloat and enable selective recomputation. A proposed offline “sleep phase” lets specialist agents analyze traces and suggest refactoring, tests, context policies, or new AKUs. Candidates do not rewrite production directly; they undergo replay, adversarial evaluation, review, staged promotion, and rollback. This is controlled harness research, not unrestricted recursive self-improvement.

Why read the complete book

A ten-minute synthesis omits the technical comparisons that make the architectural claims usable. The complete book details routing, graph execution, memory layers, context policies, verification loops, transaction semantics, security threats, protocol boundaries, evaluation design, model cascades, parallel scheduling, and cost functions. It also explains why reasoning traces are interfaces rather than faithful mental records and why process explanations—tools used, evidence selected, checks run, authority exercised, and information omitted—are more defensible than raw chain-of-thought disclosure.

The full treatment is especially necessary for assessing ScriptaHubAgentLib and MRP-VM. It specifies their components, differences from classical agent skills, multi-agent and database arrangements, self-research lifecycle, sleep-phase risks, ablations, governance requirements, and limitations. It also connects European trustworthy-AI principles and legal pressure to concrete runtime controls. Without those qualifications, “bounded delegation” can sound like a slogan; with them, it becomes a research program whose claims are configuration-specific, falsifiable, and explicitly constrained by security, privacy, evaluator quality, and local evidence.
